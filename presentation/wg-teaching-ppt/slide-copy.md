# WG-01～WG-17 教學簡報文案

## Slide 01｜封面
- 類型：封面
- 標題：從 Python 基礎到會記憶的 AI Agent
- 副標：用 17 個挑戰，把一支小程式慢慢長成像助手一樣的系統
- 頁面文字：
  - 你會看到：輸出、互動、記憶、工具、存檔、長期整理
  - 目標不是背語法，而是看懂「能力怎麼一層一層加上去」
- 視覺說明：大主視覺，放 AI 助教、終端機、對話泡泡

## Slide 02｜全局地圖
- 類型：地圖頁
- 標題：今天我們會走過哪 7 段升級路線？
- 頁面文字：
  - 1. 先讓程式說出第一句話
  - 2. 替 Agent 備好套件和設定
  - 3. 把流程收進 `main()`
  - 4. 開始和大模型聊天
  - 5. 讓它記得上一輪
  - 6. 把對話存進檔案
  - 7. 對話太長時，學會整理記憶
- 視覺說明：7 格路線圖，由淺到深

## Slide 03｜WG-01
- 類型：內容頁
- 標題：WG-01｜按下啟動鍵
- 副標：先讓 Python 在正確的時機說第一句話
- 頁面文字：
  - `print()` 可以把文字送到終端機
  - `if __name__ == "__main__"` 代表「只有直接執行這個檔案時才跑」
  - 這樣做的好處是：被別的檔案 `import` 時，不會自己亂執行
- 視覺說明：左邊是直接執行，右邊是被 import

## Slide 04｜WG-02～03
- 類型：內容頁
- 標題：WG-02～WG-03｜字串先有名字，再組成一句話
- 副標：從單純印字，到用變數和 f-string 組句
- 頁面文字：
  - 變數像幫資料貼標籤，之後可以重複拿來用
  - f-string 可以把變數直接塞進句子裡
  - 如果先後順序寫錯，後面的句子就找不到前面的變數
- 視覺說明：兩個變數盒子，箭頭接到一句完整自我介紹

## Slide 05｜WG-04
- 類型：內容頁
- 標題：WG-04｜把工具裝進專案
- 副標：先把未來要用的套件安裝好，再在檔案頂端匯入
- 頁面文字：
  - `uv add` 是把套件加進這個專案
  - `import` / `from ... import ...` 是在程式裡把名稱拿進來
  - 這一題先備料，還不急著真的打 API
- 視覺說明：專案資料夾 + 終端機安裝命令

## Slide 06｜WG-05
- 類型：內容頁
- 標題：WG-05｜讀設定，但不把金鑰秀出來
- 副標：會讀 `.env` 很重要，會保護敏感資訊更重要
- 頁面文字：
  - `load_dotenv()` 先把 `.env` 的資料載進環境
  - `os.getenv("OPENAI_API_KEY")` 再把指定變數讀出來
  - 螢幕上只能顯示「有 / 無」，不要把整串金鑰印出來
- 視覺說明：鎖頭、`.env` 檔案、被遮住的 key

## Slide 07｜WG-06～07
- 類型：內容頁
- 標題：WG-06～WG-07｜有鑰匙才往下走
- 副標：用分支決定流程，再把主流程收進 `main()`
- 頁面文字：
  - `if / else` 讓程式能根據條件走不同路
  - 沒有 API key 時，應該提早停下來，而不是硬往下跑
  - `main()` 讓「程式入口」和「主要流程」分開，結構更清楚
- 視覺說明：流程圖，入口只呼叫 `main()`

## Slide 08｜WG-08
- 類型：內容頁
- 標題：WG-08｜第一通打進大模型
- 副標：第一次從本機程式把一句話送到模型，再拿回回覆
- 頁面文字：
  - `ChatOpenAI(...)` 是建立模型連線物件
  - `invoke(...)` 代表送出一次請求
  - 回來的不是普通字串，所以通常要用 `.content` 拿文字
- 視覺說明：本機 -> API -> 模型 -> 回應

## Slide 09｜WG-09
- 類型：內容頁
- 標題：WG-09｜把一次問答變成聊天迴圈
- 副標：不再只問一次，而是可以持續對話到你說停
- 頁面文字：
  - `while True` 可以讓聊天一直重複
  - `input()` 讓使用者每輪都能打新問題
  - `quit / exit / q` 這類指令可以安全結束聊天
- 視覺說明：圓形迴圈，標上「你輸入 -> 模型回答 -> 再來一輪」

## Slide 10｜WG-10
- 類型：內容頁
- 標題：WG-10｜讓回答像打字機一樣出現
- 副標：從一次跳出整段，到一小塊一小塊印出來
- 頁面文字：
  - `invoke` 比較像等整份答案做好再拿到
  - `stream` 比較像邊生成、邊送回來
  - 對使用者來說，串流的體感通常更像真的聊天
- 視覺說明：左邊整段跳出，右邊逐字冒出

## Slide 11｜小結一
- 類型：過場頁
- 標題：前 10 題，我們做到了什麼？
- 頁面文字：
  - 從 `print("Hello, World!")` 走到「可以和模型來回聊天」
  - 已經用到：變數、條件、迴圈、函式、模組、環境變數
  - 接下來的重點是：讓模型不只會回，還要會記得
- 視覺說明：能力升級條

## Slide 12｜WG-11
- 類型：內容頁
- 標題：WG-11｜把上一輪也帶進下一輪
- 副標：聊天之所以像聊天，是因為模型看得到前情提要
- 頁面文字：
  - `messages` 是放在 RAM 裡的對話時間軸
  - 裡面不只放使用者，也要放助手，不然脈絡會斷掉
  - 這時候記憶還沒寫進檔案，所以關程式就會消失
- 視覺說明：Human / AI 交錯的時間軸

## Slide 13｜WG-11 圖解
- 類型：圖解頁
- 標題：為什麼要先組 `context_messages`，再 append？
- 頁面文字：
  - 送進模型的是「本輪要看的完整上下文」
  - 真正累積在 `messages` 裡的是「已經完成的回合」
  - 先組、再 append，才不會把未完成的回合提早寫進歷史
- 視覺說明：兩條串列，一條是送模，一條是累積

## Slide 14｜WG-12
- 類型：內容頁
- 標題：WG-12｜把人設放進 system
- 副標：有些規則不是這一輪才說，而是每一輪都要一起帶進去
- 頁面文字：
  - `SystemMessage` 是固定規則、人設、語氣的地方
  - `history` 放的是對話回合，不要把 system 混在裡面
  - 送模時常見的組法是：`[system, *history, human]`
- 視覺說明：system / history / human 三層圖

## Slide 15｜WG-13
- 類型：內容頁
- 標題：WG-13｜模型不只會想，還會用工具
- 副標：需要計算、查資料時，模型可以自己決定要不要呼叫工具
- 頁面文字：
  - `@tool` 是把 Python 函式包成可被模型呼叫的工具
  - `bind_tools()` 讓模型知道有哪些工具可以用
  - `tool_calls` 和 `ToolMessage` 讓「叫工具 -> 拿結果 -> 繼續回答」串起來
- 視覺說明：ReAct 流程圖

## Slide 16｜WG-14
- 類型：內容頁
- 標題：WG-14｜先學會把對話寫進檔案
- 副標：聊天如果只在 RAM 裡，關掉就沒了；寫進檔案才留得住
- 頁面文字：
  - JSONL 可以想成「一行一筆資料」的文字檔
  - 第一行常放 metadata，後面每行放一則對話
  - 這一題先練寫出去，不急著一開機就讀回來
- 視覺說明：`session.jsonl` 剖面，第一行 metadata、下面多行對話

## Slide 17｜WG-15
- 類型：內容頁
- 標題：WG-15｜重開程式，昨天的對話還在
- 副標：把 JSONL 再讀回來，讓程式不是每次都從零開始
- 頁面文字：
  - `json.loads()` 可以把每一行 JSON 讀回 Python 資料
  - 壞掉的行可以略過，不要讓整份檔案直接報廢
  - 這樣一來，關掉程式再打開，也能接著聊
- 視覺說明：關機 -> 開機 -> 讀檔 -> 繼續聊天

## Slide 18｜RAM vs 檔案
- 類型：比較頁
- 標題：RAM 記憶和檔案記憶，到底差在哪？
- 頁面文字：
  - RAM 快，但程式一關就忘
  - 檔案慢一點，但可以跨次執行保留
  - 真正有用的聊天系統，通常兩種都會一起用
- 視覺說明：左 RAM、右硬碟的比較卡片

## Slide 19｜WG-16
- 類型：內容頁
- 標題：WG-16｜上下文不是無限大
- 副標：對話越來越長時，不能什麼都塞進模型
- 頁面文字：
  - `history` 是完整歷史，但送進模型的可能只是其中一段 `past`
  - `TOKEN_BUDGET` 是簡化版的容量上限
  - 當容量不夠，就得從最舊的部分開始裁掉
- 視覺說明：容量尺 + 視窗框住最近對話

## Slide 20｜WG-16 圖解
- 類型：圖解頁
- 標題：裁切不是亂砍，而是有邊界的整理
- 頁面文字：
  - 本輪 `human_message` 一定要保留
  - 邊界通常選在 user-turn 開頭，避免把一段對話切碎
  - 所以 `history` 的長度，和送進模型的長度，不一定一樣
- 視覺說明：剪刀只剪舊訊息，最新輸入被框起來保留

## Slide 21｜WG-17
- 類型：內容頁
- 標題：WG-17｜把舊對話濃縮成長期記憶
- 副標：短期視窗裝不下，就把舊內容整理成更短、但還有用的摘要
- 頁面文字：
  - `MEMORY.md` 放濃縮後的長期重點
  - `HISTORY.md` 記錄每次整併發生了什麼
  - 這樣模型就算沒看到完整舊對話，還是能抓到大方向
- 視覺說明：舊對話 -> 摘要 -> 長期記憶檔

## Slide 22｜WG-17 圖解
- 類型：圖解頁
- 標題：Long-term Memory 怎麼回到模型腦中？
- 頁面文字：
  - 長期記憶不是當一般聊天訊息塞回去
  - 它會被放進 system 區塊，變成模型每輪都會看到的背景知識
  - 這樣做比把全部舊訊息硬塞回去更省空間
- 視覺說明：`MEMORY.md` -> `## Long-term Memory` -> `SystemMessage`
